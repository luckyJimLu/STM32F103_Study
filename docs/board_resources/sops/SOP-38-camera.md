## 1. 实验目标

- 在裸机基线中复现“摄像头”实验并保留可测量结果。
- 把底层驱动与业务逻辑分离，形成可被 RTOS 任务安全调用的接口。
- 对超时、资源冲突和失败恢复给出明确行为。

## 2. 前置条件与资源

- 前置能力：摄像头寄存器、像素时钟、显示、外部 FIFO。
- 硬件/外设：OV7725 摄像头、P6、TFTLCD、FIFO/控制信号。
- 通用参考：[开发板硬件速查](../01_board_quick_reference.md)；接线、供电和复用关系以 V1.2 原书及实物原理图为准。
- 开始前保存当前时钟树、引脚复用、NVIC 和链接内存配置，避免覆盖已有实验资源。

## 3. RTOS 设计

摄像头任务控制帧采集，完成中断通知；帧/行缓冲通过有界队列送显示或处理任务。

通用约束：中断中只清标志、采集最小数据并使用 FromISR/ISR-safe API 通知任务；共享外设由单一服务任务或带优先级继承的互斥量保护；所有等待必须有超时和错误统计。

## 4. 操作步骤

1. 核对 P6 方向和所有控制/数据线，读取摄像头 ID。
2. 配置低分辨率/低帧率，先验证彩条或实时预览。
3. 测量采集、搬运、显示耗时，设置丢帧和背压策略。
4. 把裸机示例中的长轮询或延时替换为状态机、任务阻塞等待或硬件触发。
5. 增加错误码、超时计数和关键状态日志；验证失败后可以重新初始化，而不是只能复位。
6. 在正常负载与压力负载下重复测试，并记录 CPU 占用、任务栈高水位和队列峰值。

## 5. 验收标准

- 功能：预览颜色和方向正确；持续运行不花屏、死锁或耗尽内存，丢帧可统计。
- 实时性：关键中断不执行格式化输出、文件访问或长时间轮询；高优先级任务能按设计期限运行。
- 健壮性：断开外设、输入非法数据或制造超时后，驱动返回可诊断错误，系统其他任务继续运行。
- 可维护性：底层驱动、RTOS 适配层和应用逻辑分层，业务代码不直接依赖 HAL 全局句柄。

## 6. 风险与排障

- F103 SRAM 和总线带宽很紧；避免整帧多份拷贝，优先 FIFO+条带/行缓冲。
- 若结果与原书不同，依次核查：板卡/模块版本、跳帽与供电、时钟树、GPIO 复用、NVIC 优先级、共享总线占用和 RTOS 栈空间。
- 建议保留一个最小裸机自检工程；遇到 RTOS 问题时先用它区分硬件/驱动问题与调度/同步问题。

## 7. 交付物

- 可复现的最小测试程序或测试命令。
- 一份资源声明：GPIO、DMA 通道、定时器、IRQ、任务优先级、栈和队列容量。
- 验收记录：测试条件、实测结果、失败注入结果和已知限制。
